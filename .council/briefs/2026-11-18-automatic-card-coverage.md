# Automatic issuer coverage check — review only

The Chairman's 18 November direction to automate card coverage authorises this bounded public-issuer coverage check. Record only public source routes and operational dispositions. Do not copy private research or alter its original dated intake.

The operating gap is discovery and reconciliation, not approval. Keep genuinely verified live cards, named research rows, specific whole-product holds, confirmed closures, and insufficient/unavailable source evidence separate. Links and visibility from an issuer catalogue are leads; differences or probed absences never set eligibility, confirm closures, refresh financial facts or declare publishable coverage. The three DIB Skywards closures rely on the partner's dated notice, not the missing-link rule.

The authorised schedule uses standard public source requests, no paid provider, credential, GitHub issue or PR creation, site change, new article, analytics or subscriber communication. Scope remains limited to this card check; do not change the existing Newswire/hosted news monitors or editorial shifts. Evidence updates and future card additions remain separate protected releases. Require reproducible offline tests, independent T3 review, an exact-head hosted check and a controlled read-only hosted run before representing the workflow as operational.

GitHub is public. Hosted summaries contain aggregate counts only; detailed receipts stay local. For a local review of two independently identified, successful receipts, run `node scripts/monitor/card-coverage-delta.mjs current.json --prior previous.json`. A changed HTML fingerprint means the source merits a check, not that card terms changed.
